# IRISiv — Frontend Developer Complete Task Specification

## 1. Your Role

You are responsible for building the **entire frontend/UI of IRISiv**.

Your responsibility is to create a **professional, responsive, production-style web application** through which the three main users of IRISiv can interact with the platform:

1. **NGO**
2. **Corporate**
3. **Business/Vendor**

The frontend must represent the complete IRISiv CSR lifecycle:

> **NGO Need → CSR Project → Corporate Approval → Business Proposals → AI Evaluation → Business Selection → Contract → Advance Payment → Project Execution → Delivery → NGO Verification → AI Verification → Final Payment → Impact Report**

This lifecycle is the core workflow of the project. 

---

# 2. Your Main Objective

Your goal is **not just to create attractive dashboards**.

The frontend must make the entire IRISiv workflow understandable and usable.

A judge should be able to open the application and understand:

> **Who is doing what, what stage the CSR project is currently in, what happened previously, and what needs to happen next.**

The UI should therefore make the **project lifecycle extremely clear**.

---

# 3. Technology Requirements

Use:

* **Next.js**
* **TypeScript**
* **Tailwind CSS**
* **shadcn/ui**
* **Lucide React**
* **Framer Motion** where animation genuinely improves UX

Do not introduce another frontend framework without discussing it with the team.

---

# 4. Important Architecture Rule

You are the **frontend developer**.

Therefore:

### You ARE responsible for:

* Pages
* Components
* Layout
* Navigation
* Forms
* Tables
* Cards
* Modals
* Dialogs
* Charts/UI
* Loading states
* Error states
* Empty states
* Responsive design
* API integration from frontend
* Frontend validation
* User experience

### You are NOT responsible for:

* Database schema design
* PostgreSQL migrations
* RLS policies
* Backend business logic
* AI model implementation
* Payment infrastructure
* Server-side authorization logic

Those belong to other team members.

You should consume the APIs provided by the backend developer.

# 🔥 The most important instruction to Person 1

Tell them this:

> **"Don't think of this as building three dashboards. You are building the visual interface of one complete CSR lifecycle. Every screen must connect to the same project and clearly show what happened before, what is happening now, and what happens next."**

The frontend should make the IRISiv story obvious **without you needing to explain every screen verbally**.

The underlying workflow is the one we've finalized from the project document: NGO need → CSR project → corporate approval/funding → business proposals → AI evaluation → business selection → execution → NGO evidence/verification → AI verification → final payment → impact report. 

### **In short: Person 1 owns everything from `User clicks something` → `User sees the result`.**

Backend owns **what happens behind that click**.
Database owns **where the data lives**.
You own **AI + advanced integration**.

That separation will keep the team clean and prevent the classic hackathon problem where everyone edits the same files and nobody knows what belongs to whom.
